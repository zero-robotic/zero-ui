# 子树缓存与区域重绘测量

测量日期：2026-11-12；macOS 27.2（26B123）、arm64、Rust 1.98.1。基线为 `bd3d597`，包含上一轮整帧 CPU 缓存；优化版使用同一 `refresh-bench` 场景，增加最后一帧区域像素计数。架构、预算和像素精度说明见 [区域绘制](../../region-rendering.md)。

## 方法

- Release 构建，800×480、scale=1，固定仓库字体；每场景预热 20 帧，采样 120 帧。
- 三轮顺序为 before/after、after/before、before/after；测量期间没有同时编译或运行测试。表中 P50/P95 分别取三轮的中位数。
- 包含事件处理、View 协调、布局、Scene 生成和 CPU 渲染；不包含原生窗口提交、显示器刷新或输入到屏幕延迟。
- 每个采样帧在计时区间外计算像素哈希，累积成校验和；六个场景的三轮前后校验和均完全一致。
- 当前基准主动调用 draw/render，静态场景数据不是原生窗口空闲 CPU 占用。原生循环无更新时使用 Wait，无周期性重绘。
- 基线从 `git archive bd3d597` 构建，优化版从当前工作树构建，使用各自保存的可执行文件交替测量。若共用 Cargo target，切换源码后须清理工作区 crate 的构建产物，避免不同源码目录间的指纹缓存混用；复现推荐使用独立 target 目录。

## 结果

单位为微秒；降低比例按 P50 计算。原始 CSV 保留于本目录。

| 场景 | 基线 P50 | 优化 P50 | 基线 P95 | 优化 P95 | P50 降低 | 最后帧栅格化像素 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 局部文字 | 1408.666 | 238.541 | 1572.833 | 310.958 | 83.1% | 4,096 / 384,000 |
| 局部颜色 | 1244.583 | 114.209 | 1410.208 | 161.208 | 90.8% | 4,096 / 384,000 |
| 弹出层增删 | 1417.583 | 295.042 | 1570.583 | 395.834 | 79.2% | 24,576 / 384,000 |
| 连续 32 次 Wake | 1349.000 | 236.166 | 1481.500 | 321.292 | 82.5% | 4,096 / 384,000 |
| 连续 32 次指针移动 | 296.833 | 275.708 | 367.208 | 335.458 | 7.1% | 0 / 384,000 |
| 静态虚拟列表 | 8.500 | 1.875 | 21.459 | 7.416 | 77.9% | 0 / 384,000 |

局部更新的主要收益来自跳过无关文字/路径的渲染和只栅格化变化区域。命令缓存不会消除最终扁平 Scene 的组合成本，也不改变完整布局引擎的算法；指针事件仍按顺序全部派发。因此不能把这个结果解释为所有 UI 操作都获得同样加速。

这份表是 CPU 实测，不能用于推断 GPU 加速倍数。后续 GPU 时间戳与端到端渲染帧时间补测见 [GPU 区域重绘测量](../gpu-regions/README.md)。

## 复现

```sh
cargo run -p zui-window-check --example refresh-bench --release --locked -- 120
```

基准同时输出 P50/P95、各阶段时间、排版/布局计数、逐帧累积校验和、最后帧实际栅格化像素及总像素。真实应用可通过 `paint_cache_stats()` / `damage_stats()` 检查是否命中预期复用路径。
