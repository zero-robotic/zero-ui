# GPU 区域重绘补测

2026-11-12，Apple M2 Pro，Metal，macOS 27.2（26B123），Rust 1.98.1，Release 构建。

## 结论

- 局部文字、颜色、弹出层更新的端到端渲染帧 P50 在 1× 降低 60.7%～68.9%，2× 降低 67.2%～76.9%。这是实际等待 GPU 完成的结果，不只是 CPU 提交时间。
- 当前数据**不能证明纯 GPU 执行加速**。局部更新的带插桩 GPU 区间反而较长：区域提交、区域复制和全屏呈现增加工作，时间戳标记本身也有额外开销。端到端收益主要与 CPU 端减少无关文字/路径回放及提交准备相符。
- 全屏变化没有收益：端到端 P50 在 1×/2× 分别增加约 0.7%/2.0%；这类小差异也可能受运行波动影响。区域缓存不是所有场景都更快。
- 无变化时强制呈现可复用纹理；这不等于测量了空闲 CPU 占用。实际窗口无更新时应不绘制。

## 测量口径

同一工作树、同一程序的两种模式：`full` 设置 `max_pixel_bytes = 0`，直接整帧绘制到目标；`retained` 使用默认区域缓存，包括最终全屏纹理复制。两者都保留当前核心层的子树命令缓存，比较的是 GPU 渲染策略，**不是历史提交与当前版本的总差异**。

- 逻辑尺寸 800×480，物理尺寸分别为 800×480 和 1600×960；仓库固定字体、120 个标签，沿用 CPU refresh 基准的六个场景，另加全部标签变色 `full_damage`。
- 每场景每种测量预热 30 帧、采样 120 帧；每个缩放做三轮，顺序 full/retained、retained/full、full/retained。没有同时编译或运行其他项目测试。表中分别取三轮 P50/P95 的中位数，不是把所有帧混在一起求分位数。
- **端到端渲染帧**：事件批次处理 → View/协调/布局 → Scene → 渲染准备与提交 → `Device::poll(wait_indefinitely)` 确认 GPU 完成。关闭时间戳插桩，没有像素回读；CSV 的 `submit_*` 仅计到提交返回。
- **不包含**原生交换链获取、系统合成、VSync、扫描输出与真实输入设备延迟。目标是无窗口纹理，因此不是 input-to-photon 测量，也不能将倒数当作实际窗口 FPS。逐帧等待用于隔离单帧延迟，不代表多帧在途的吞吐量。
- **GPU 区间**另起一次相同工作负载采样。用硬件时间戳求每个渲染 command buffer 的开始到结束，再逐帧相加；覆盖区域绘制/复制与最终呈现，排除查询结果回读和各提交之间的 CPU 空隙。它不是纯着色器活跃时间。
- M2 Pro 不提供 `TIMESTAMP_QUERY_INSIDE_ENCODERS`。采用与实际输出纹理有依赖的渲染标记通道，前后保留附件、禁止颜色写入，以防独立计算标记被重排而漏计。每次提交增加两个标记通道，包含额外 load/store、同步和标记绘制成本；局部更新通常两次提交，整帧直接绘制一次，**插桩扰动不相同，不能据此断言未插桩 GPU 慢了相同比例**。不对标记开销做未经验证的扣除。
- GPU 完成后单独解析查询并读取计数；零值或逆序时间戳报错，不记为零耗时。探索阶段的空通道/独立计算通道数据均未纳入报告。最终 12 次基准运行全部成功，没有丢弃异常帧或选择性重跑。

## 复现与验证

```sh
cargo build -p zui-window-check --example gpu-refresh-bench --release --no-default-features --features gpu-bench --locked
target/release/examples/gpu-refresh-bench full 120 1
target/release/examples/gpu-refresh-bench retained 120 1
target/release/examples/gpu-refresh-bench retained 120 2
target/release/examples/gpu-refresh-bench full 120 2
cargo test -p zui-render-gpu --features profiling --locked presentation_copies_retained_pixels -- --include-ignored
```

本目录 `{full,retained}-{1,2}x-{1,2,3}.csv` 是 12 次运行各场景的汇总数据，保留 P50/P95、提交时间、最后帧栅格化像素；不是逐帧原始样本。像素正确性在独立真实 GPU 测试中验证，开启插桩后仍要求呈现纹理与完整绘制一致，并检查时间戳为正、读取后计数清零。基准计时区间内不插入像素校验回读。

后续若要判断纯 GPU 工作量是否降低，应使用能直接观测实际 Vello 渲染通道的原生 GPU profiler，避免额外标记通道；若要测真实窗口交互延迟，还需单独包含交换链和显示链路。当前结果只支持“局部更新的端到端渲染延迟显著下降”，不支持“所有场景 GPU 本身都更快”。
