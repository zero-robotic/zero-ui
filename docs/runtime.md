## 声明式 View 与持久控件协调

状态：基础协议、根视图协调、文字与标准容器已实现；窗口输入与同步应用消息基础已接通，完整交互控件和异步调度仍在后续阶段。


<a id="view-reconciliation--1-职责与接口"></a>

### 1. 职责与接口

`zui-api::view::View` 是当前界面的描述，包含布局样式、可选 Key、裁剪标记、子视图及类型擦除后的属性描述。`ViewSpec` 由控件作者实现，关联一个具体 `Widget` 类型：

- `build`：仅在需要新实例时创建持久控件，不在每次生成 View 时运行。
- `update`：把新属性应用到已有实例，保留仍然有效的局部状态，返回 `None`、`Paint` 或 `Layout` 失效级别。

`zui-core::Tree::from_view` 创建树，`Tree::reconcile` 接受新的完整根视图，负责复用、更新、插入和卸载。核心只通过公共协议与通用类型身份判断兼容性，不引用任何具体控件类型。布局和渲染仍使用原有独立契约。

属性描述与持久状态必须分开。例如 MeterView 保存当前数值与颜色；Meter 保存实际控件实例。文本控件未来可在属性不改变其语义时保留光标和选择，但具体保留规则由该控件的 `update` 决定。


<a id="view-reconciliation--2-身份规则"></a>

### 2. 身份规则

| 情况 | 规则 |
| --- | --- |
| 同一被复用父节点下，有 Key 且控件类型一致 | 按 Key 复用，重排保留 NodeId 和局部状态 |
| 无 Key，原来相同绝对位置也是无 Key 且类型一致 | 按该位置复用；不表示业务数据身份相同 |
| Key 相同但控件类型不同 | 替换整个子树；不把旧状态转交给新类型 |
| 根 Key 或根控件类型改变 | 替换根及全部子树，分配新 ID |
| 节点被移除后重新出现 | 创建新实例，不复活已卸载状态 |
| 相同 Key 位于不同父节点下 | 互不关联；声明式跨父节点移动不复用原实例 |
| 同一父节点有重复 Key | 返回 `DuplicateKey`，整次协调不修改原树 |

Key 支持数字和字符串，两类值彼此不同。动态列表应使用稳定业务 Key，不能以当前列表索引替代数据身份。没有 Key 的位置匹配适合结构固定的内容。数字索引只适合数据身份和顺序确实固定的预览。

命令式 `reparent` 保留现有实例，但不能导致目标父节点下出现重复 Key。对于默认的声明式子项，完整 View 将重新决定该树结构；显式声明为控件管理的子项按第 5 节处理。应用应明确谁拥有结构更新职责。


<a id="view-reconciliation--3-协调过程与失败行为"></a>

### 3. 协调过程与失败行为

1. 检查全部新视图的节点数、深度、叶节点约束及兄弟 Key 唯一性。
2. 根据现有身份和控件类型生成复用计划，并检查新 ID 的可分配范围。
3. 卸载不再使用的节点，子节点先于父节点。
4. 对复用节点更新属性；对新节点创建实例并挂载，父节点先于子节点。
5. 合并属性、样式、裁剪和子节点顺序引起的失效。

所有返回的结构/预算/身份分配错误均发生在控件回调之前，因此不会留下部分属性更新或生命周期调用。控件作者的构建、更新和生命周期回调属于无失败返回的契约，不提供 panic 事务恢复。可能失败的数据解析、资源配置验证应在生成 View 前完成；布局数值校验仍由布局实现执行。

未变化的属性应返回 `Invalidation::None`；颜色等变化返回 `Paint`；影响测量的内容或字体等变化返回 `Layout`。控件作者必须准确报告；核心不能推断自定义属性的尺寸语义。结构或布局样式变化由核心自动提升为布局失效。已有待处理失效不会被一次无变化的协调清除。


<a id="view-reconciliation--4-局部子项协调"></a>

### 4. 局部子项协调

`Tree::reconcile_children(parent, views)` 替换指定父节点的完整子项描述集合，父节点自身的属性、样式和身份不变，无关分支不执行 ViewSpec::update。父节点可以是根，也可以是深层容器。它与完整根协调共用 Key/类型匹配、结构验证、计划生成和卸载逻辑，不定义第二套身份规则。

接口接受已生成的 `Vec<View>`，不负责选择可见范围或调用行工厂。上层可在范围变化后仅提交需要保留的子项；被省略的子树会卸载，焦点丢失和指针捕获丢失通知发生在卸载之前。仍在集合内的匹配节点保留身份与有效输入所有权。当前不自动保活屏幕外的焦点行，列表所有者需要先明确保留或迁移策略。

预算依据“未受影响节点 + 新子项全部后代”的最终节点总数计算，深度从实际父节点继续计数。相同规模替换不会因为旧节点暂时存在而重复扣预算。重复 Key、非法叶节点、超预算和 ID 耗尽在任何控件回调或树修改前拒绝。回调 panic 不承诺恢复。

返回报告只统计提交子项中的创建、复用和删除，不把保持不变的父节点计入复用数；invalidation 仍表示整棵树合并后的失效。重排、插入、删除会要求布局，无变化更新不强制布局。当前布局仍是原有全树布局，局部协调不等于局部布局缓存。

默认声明式模式下，后续完整 `reconcile` 仍以提交的根描述为准，会覆盖此前的局部结构。需要保留并自动更新生成子项的容器必须显式采用下面的控件所有权模式。局部协调本身不选择可见范围，也不提供 VirtualList 控件。


<a id="view-reconciliation--5-控件管理的子项与布局收敛"></a>

### 5. 控件管理的子项与布局收敛

`View::managed_children()` 设置 `ChildOwnership::Widget`，由持久控件的 `Widget::child_views(PaintContext)` 返回完整子项集合。普通 View 默认使用 `Declarative`，继续消费 `View.children`。控件管理模式不允许同时声明静态子项，也不允许 Leaf 布局：分别返回 `ConflictingChildOwnership` 和 `LeafHasChildren`，不静默忽略冲突输入。

相同 Key 与控件类型的所有者在根视图重建时保留已经生成的子树，不因新描述的 children 为空而卸载。切回 Declarative 后，以显式子项集合重新协调；删除所有者或改变其 Key/类型仍卸载整棵子树。保留节点照常计入整树节点预算，报告不把未执行 update 的保留后代算作复用回调。

`layout/layout_with_text` 先完成几何校验和 prepare，再调用现存所有者的子项查询，并通过通用局部协调应用结果。子项造成布局失效时再次布局；新创建的所有者等下一轮取得实际几何后才查询，已删除的所有者跳过。同一轮批量处理独立容器，后续查询使用最近发布的几何，布局依赖由下一轮重新计算。最多执行 16 轮，仍无法稳定则返回 `ChildLayoutDidNotConverge` 并保持布局失效，禁止发布未稳定的 Scene。

即使本次只有 Paint 失效、无需重新计算现有几何，也会查询生成子项，因此滚动状态改变可以触发行集合调整。直接使用 Tree 的调用方在构建 Scene 前仍需调用布局入口；WidgetHost 已有这一调用顺序，不需要识别任何具体容器。

`child_views` 是可重复执行的描述查询，不得消费一次性请求或执行外部副作用。相同状态和几何应产生可稳定匹配的描述，ViewSpec::update 应准确报告失效；每次无条件返回 Layout 会触发收敛上限。当前每轮重新生成描述，不承诺行工厂每帧只调用一次，昂贵数据准备应在上层缓存。

`Widget::children_prepared(context, children)` 为控件管理的子项提供布局反馈。它在完整几何校验和所有控件 prepare 成功后调用，先于本轮 child_views 查询。ChildLayout 快照按当前兄弟顺序包含直接子项的 NodeId、Key、可选 LayoutTag 和 LayoutBox；坐标相对父节点，不叠加 child_viewport 或祖先变换，不返回后代节点或具体控件引用。空容器首次反馈为空，新增子项在下一次实际布局后反馈尺寸。

反馈只在布局真正执行时触发，纯 Paint 刷新不会重复报告已有尺寸。回调可更新自身尺寸缓存、估值或索引：如果改变测量结果，应返回 Layout；如果只改变后续描述或呈现，应返回 Paint；无变化返回 None。后续 child_views 与协调仍负责修改结构，反馈回调本身没有树访问权。新失效进入同一个 16 轮收敛上限，不另启无界循环。

布局输出不完整或任一 prepare 失败时，本轮不调用子项反馈。反馈自身返回错误会保持布局失效并阻止 Scene；此前成功回调的本地状态不回滚，修正后重试。View::layout_tagged 可设置父级自定义的代次/值关联标签，核心原样传递，不解释其含义；标签变化保留 NodeId 并请求新布局，保证反馈来自当前标签对应的描述。快照拥有 Key 副本，修改或保留快照不改变树；NodeId 的有效性仍由后续节点生命周期决定。

单次子项协调的结构错误仍在回调前拒绝，但多个所有者和多轮布局不构成全树事务：后续失败时，先前成功的更新和生命周期已经发生，不会回滚。错误会将树标为布局失效；修正状态后可重新调用布局恢复。子项查询返回 LayoutError 时同样阻止绘制。焦点/捕获策略沿用第 4 节，不自动保活被省略的行。

控件层已使用当前机制实现 [VirtualList：固定、显式与自动行高](layout.md#virtual-list)，包括范围联动和局部原点；虚拟焦点导航与完整状态保活策略尚未实现。


<a id="view-reconciliation--6-已验证与后续范围"></a>

### 6. 已验证与后续范围

`crates/zui-core/tests/reconcile.rs` 覆盖重排、插入、删除后再插入、无 Key 混排、类型变化、根身份替换、重复 Key、结构预算及不必要重建的避免。独立 `examples/custom-widget` 提供 `MeterView`，顶层像素测试将属性从 25% 改为 75%，再以声明式方式设为 50%，确认复用同一实例且跳过布局，CPU/GPU 均检查全部输出像素。

当前 API 是通用描述协议，`row(...)` 等标准容器构造函数已实现；核心焦点与鼠标捕获跟随稳定节点身份，删除时清理。同步控件动作到应用消息的映射已接入 Host；异步消息队列、组件状态作用域、完整焦点域/选择恢复和虚拟列表编辑行保活仍待实现。基础协调不代表完整声明式应用运行时已完成。

`owned_children.rs` 覆盖布局尺寸反馈、Paint 更新生成子项、根重建保留、切换所有权、失败恢复、100 个独立容器批量收敛、16 轮上限、显式子项冲突、生成节点的预算统计，以及嵌套所有者等待几何和移除后不再查询。

`child_layout_feedback.rs` 核心测试覆盖准备顺序、Key/节点/布局快照、局部坐标、反馈改变描述后的收敛、纯 Paint 跳过反馈、错误重试、不完整布局/prepare 失败时不通知及有界循环；顶层同名集成测试通过 Taffy 和 Parley 验证真实文字随视口变窄而增加高度，反馈尺寸与发布的布局一致。

## 控件事件、焦点与鼠标捕获

状态：核心事件基础已接入 `WidgetHost` 的窗口输入路径，并通过事件到应用消息的契约集成测试；标准交互控件和真实点击操作仍待后续验证。


<a id="events--契约与依赖"></a>

### 契约与依赖

`zui-input` 定义平台与 UI 共用的输入值，采用 `no_std + alloc`，仅依赖基础类型。`zui-platform` 保留原重导出入口以及窗口生命周期事件；`zui-api::event` 重导出输入值并定义 `WidgetEvent`、`EventContext`、`EventResponse`。两者互不依赖。

控件实现 `Widget::event` 接收事件，返回处理状态、传播控制、失效、焦点/捕获请求以及动作；核心不识别具体控件。事件回调只能修改控件自身状态，不接收可变 Tree，因此不会在传播期间直接改变路径和拓扑。应用消息映射在传播完成后由 Host 调用，避免在派发过程中改变树。


<a id="events--路由规则"></a>

### 路由规则

调用 `Tree::dispatch_input` 前必须完成布局；布局失效时返回 `LayoutRequired`。鼠标使用当前命中测试，遵守已有平移、裁剪与逆绘制顺序。有鼠标捕获时目标改为捕获节点，坐标允许位于其边界之外。没有新坐标的鼠标事件使用最后已知位置重新命中。

传播顺序为祖先从根向下的 Capture 阶段、目标的 Target 阶段、祖先从近到远的 Bubble 阶段。目标不重复接收 Capture/Bubble。指针位置转换为每个接收者的逻辑局部坐标；平台已去除 DPI 比例，核心不再重复缩放。


<a id="events--控件内部交互区域"></a>

#### 控件内部交互区域

路由输入的 `EventContext.geometry` 为 `Some(EventGeometry)`，包含接收者的边框盒 `size` 与扣除 padding 的 `content_bounds`。两者均为接收者局部逻辑坐标，与 `PaintContext` 使用同一内容区域计算；指针位置仍相对边框盒原点。控件可先检查指针是否位于内容区域，再减去内容区域原点，得到内部选项或轨道的坐标。捕获期间指针可以在边界外，不会被强行截断。

几何数据来自成功提交的布局，首次绘制前即可使用；控件不需要缓存上次 paint 的尺寸，也不需要访问核心树。键盘与 IME 路由同样携带几何信息，但 `local_position` 为 None。Direct 通知的 `geometry` 始终为 None，因为取消捕获、失焦或移除通知可能发生在布局失效期间；通知只用于清理交互状态，不能据此进行新的位置命中。

每次传播使用已提交的几何，即使前一个接收者请求 Layout 失效，本次传播仍使用该布局；下一次输入必须重新布局。几何快照只包含 ZUI 值类型，不暴露布局引擎、核心节点或可变内部状态。

`handled` 抑制默认行为，例如 Tab 导航，但不停止传播；`stop_propagation` 停止后续接收者，两者独立。传播使用当前路径快照，一个回调报告布局失效不会中断本次路径，下一次输入前必须重新布局。`DispatchResult` 给出本次原始路由目标、是否处理，以及树累计的失效状态。

焦点请求支持 Focus（接收者自身）、Target(NodeId)（当前树中的指定节点）与 Clear；指针捕获请求仍只指向接收者自身。按传播顺序采用首个有效请求，在本次传播结束后应用。控件若自行处理 Tab 并请求焦点，应同时标记 handled，避免默认导航继续运行。

Target 请求要求接收者 enabled，且目标存在、enabled、focusable；无效请求被忽略，后续接收者仍可提出有效请求，不使整个事件派发报错。核心在提交前再次验证选中的目标，若被后续回调禁用或变为不可聚焦，则保持原焦点；此时不会回退尝试其他请求。目标 ID 必须来自当前树，跨树或已经卸载的身份不能当作有效导航引用。

指定焦点不会改变当前事件的路由和 target，也不会改变指针捕获。切换复用 Direct 焦点通知和祖先自动滚入；Direct 通知返回的动作与所有权请求仍被忽略。该能力只提供节点级请求，不实现焦点域、祖先禁用传播或具体控件的导航策略。


<a id="events--焦点和捕获"></a>

### 焦点和捕获

`focusable()` 默认为 false。可聚焦控件可请求焦点，键盘、修饰键和 IME 数据路由到焦点节点，而非鼠标悬停节点。未处理的 Tab/Shift+Tab 按当前树的先序遍历顺序循环导航；Control/Alt/Super 修饰的 Tab 不执行此默认行为。当前尚无 tab-index、焦点域、模态焦点约束或空间导航。

鼠标按钮按下期间可请求捕获，直到控件主动释放、所有鼠标按钮松开、节点删除或输入取消。多个按钮同时按下时，不因其中一个松开就释放捕获。当前只支持一个鼠标捕获所有者，不代表已支持触摸手势。

`FocusChanged`、`PointerCaptureLost` 和命中叶节点的进入/离开通知使用 Direct 阶段，不传播。通知只采纳失效，不接受新的焦点/捕获请求，避免递归转移。祖先 hover 状态及无输入时因布局变化而刷新 hover 尚未实现；下一鼠标输入会重新命中。

稳定 Key 重排保留节点的焦点和捕获。删除或类型替换会在 Unmounted 之前发送丢失通知；失去 focusable 能力时清除焦点。`Tree::cancel_input` 清理焦点、捕获、hover 与鼠标按钮状态；Host 已在窗口失焦、遮挡和断开时调用它。不可绘制时收到的输入取消所有权并丢弃，避免隐藏控件被激活。


<a id="events--程序化焦点"></a>

### 程序化焦点

直接管理 Tree 的装配层可调用 `Tree::request_focus(Some(node_id)) -> Result<bool, TreeError>`，或以 `None` 清除焦点。返回值表示焦点所有者是否改变；不表示目标完全可见，也不请求操作系统窗口焦点。WidgetHost 通过下面的一次性应用请求协调焦点，不暴露可变树。

目标必须是当前树中已经存在、enabled 且 focusable 的节点。不存在返回 MissingNode，不可聚焦或禁用返回 NotFocusable；这些验证失败不会改变已有焦点。当前验证目标自身，不提供祖先禁用传播或焦点域语义。成功切换复用 Direct 焦点通知和祖先自动滚入，不改变指针捕获。

布局前也可请求焦点，滚入延迟到有效布局发布后执行。重复请求同一目标不重复通知；已成功滚入后，重复请求不会覆盖用户手动滚动的位置。尚未完成的滚入仍可重试。滚入阶段出错可能发生在焦点已经切换之后，不保证回滚。细节见 [焦点与区域自动滚入](runtime.md#reveal)。

此接口不生成虚拟行。应用必须先完成索引定位和布局，再解析当前已生成节点并请求焦点；不能缓存已回收行的 NodeId 作为业务身份。


<a id="events--默认-tab-导航前的容器回调"></a>

### 默认 Tab 导航前的容器回调

普通按键传播完成后，只有未 handled 的 Tab/Shift+Tab 按下事件进入 `Widget::navigate_focus`。Control/Alt/Super 修饰和按键释放不进入；没有当前焦点时采用既有首次候选规则，并允许目标路径的进入回调参与。回调按当前焦点节点到根的顺序执行，跳过 disabled 接收者。

`FocusNavigation` 提供方向、当前焦点和默认候选 NodeId，以及它们在接收者下的直接子分支 ID。子分支不是逻辑列表索引；候选是接收者自身或位于子树外时 candidate_child 为 None，可结合 candidate 区分。没有几何或可变树访问。候选是回调前快照，不代表已经提交的焦点。

`FocusNavigationResponse` 可产生失效和应用动作；handled 为 true 时停止询问外层并抑制默认跳转，焦点仍保持原位。动作带实际接收者的 source，经已有 Host 消息通道处理，应用可重建并在 take_focus_request 中选择生成后的目标。接管方负责后续推进，不能只消费 Tab 而永久保留无效意图。

无人接管时核心重新检查可聚焦候选，按既有先序循环规则跳转；回调可能改变自身 focusable，不能直接使用旧候选。该机制不建立焦点域、不修改指针捕获，也不自动生成虚拟行。VirtualList 已通过 on_navigate 输出逻辑行请求，应用组合重建和 take_focus_request 完成跨行导航；详见 [虚拟列表导航](layout.md#virtual-list--跨行-tab-导航动作)。


<a id="events--从子树外进入焦点"></a>

### 从子树外进入焦点

离开侧 navigate_focus 未接管时，核心重新选择默认候选，并调用新进入路径上的 `Widget::enter_focus(FocusEntry)`。接收者按由外到内排列，排除与当前焦点共享的祖先；没有当前焦点时询问候选的完整路径。禁用接收者被跳过，但不引入祖先禁用传播。普通行内移动不会重新询问所属列表。

FocusEntry 包含方向、可选的原焦点、候选和接收者下的候选直接子分支；候选就是接收者时子分支为 None。返回的 FocusNavigationResponse 复用动作、失效和 handled 语义。handled 时停止剩余进入回调并保留原焦点，应用可先生成虚拟目标再提交焦点请求。离开侧已 handled、普通按键已处理或不符合 Tab 条件时不进入此流程。

无人接管时最终重新检查候选资格后提交焦点；回调不得依赖候选已经聚焦，也不提供任意状态变更后的重复导航收敛。程序化 request_focus 和指针焦点不走此入口，避免应用明确指定的目标再次被容器重定向。进入路径测试覆盖首次进入、共享祖先排除、外层优先接管、动作来源及禁用接收者。


<a id="events--应用层焦点请求"></a>

### 应用层焦点请求

`ViewApplication::take_focus_request(&mut self, tree: &Tree) -> Option<ViewFocusRequest>` 在重建和布局成功后调用。应用通过只读树按业务 Key 查找当前节点，返回 `Some(ViewFocusRequest::Focus(id))` 或 `Some(ViewFocusRequest::Clear)`；None 保持焦点不变。该方法默认返回 None，现有应用无需修改。

应用应保存待处理意图，在返回 Some 时消费，不能每次准备都重新要求焦点，也不能在此回调修改影响 View 的模型数据。一次帧内可能多次准备；目标未生成时可以保留意图并返回 None，但该回调不主动调度下一帧。模型在 update/message 中建立请求时，应同时返回 redraw 或 rebuild；需要索引跳转时提交包含新定位的 View 并请求 rebuild。

Host 在已提交布局上应用请求。焦点通知导致 Layout 失效时，再完成布局后才继续派发输入或绘制，该次准备不再次询问焦点请求。普通输入、绘制和动画唤醒路径均保持 IME 同步；旧所有者的排队 IME 数据在新会话发布前被丢弃。请求失败终止本次准备并清除已缓存 IME/动画截止时间；已消费意图不自动恢复。校验错误保留原焦点，滚入错误不保证回滚。

只读 Tree 参数属于顶层应用装配接口。核心、布局、渲染、平台及控件契约不依赖 ViewApplication，也不认识业务 Key 对应的导航含义。完整示例和远索引/IME 回归位于 `tools/window-check/tests/focus.rs`。该接口自身不解释虚拟列表策略；VirtualList 的 on_navigate 可使用它完成跨行导航，离屏编辑保活仍未实现。


<a id="events--动作到应用消息"></a>

### 动作到应用消息

`zui-api::action` 提供 `ActionId`、`WidgetAction` 和带来源 NodeId 的 `ActionEvent`。应用构建控件时指定动作 ID；控件定义其公开载荷类型，并通过 `EventResponse.actions` 输出动作。核心按传播接收顺序收集，添加真实来源节点，不解释 ID 或载荷。

载荷是进程内拥有所有权的 `Any` 值。应用在 `ViewApplication::map_action` 中结合 ID、来源及 `payload::<T>()` 检查，将其映射为自己的 `Message` 类型；`message` 再更新业务状态并返回 ViewAction。类型不匹配可返回 None，不会导致核心 downcast 或 panic。ID 命名空间和载荷匹配由应用负责，当前不提供编译期完整绑定验证，也不是跨线程/持久化消息协议。

Host 先完成事件传播，再按动作顺序映射并处理消息，合并重绘、退出和最早唤醒时间。已 handled 的原始输入不再传给窗口级 `update`，避免重复快捷键；动作本身不自动设置 handled，控件须按自身语义决定。Direct 通知仍只接收失效，动作及所有权请求均忽略。

尚不支持递归派发、异步消息队列或消息预算调度；本轮测试通过独立契约控件验证链路，正式按钮等交互控件继续后续实现。


<a id="events--验证与待办"></a>

### 验证与待办

测试覆盖嵌套路径和局部坐标、传播停止与 handled 的区别、Tab 循环、多个鼠标按钮的捕获生命周期、键盘/IME 与 hover 分离、删除前通知、Key 重排保留状态、失焦清理及非法输入拒绝。

触摸值在平台层继续保留，但核心当前对 Touch 返回 `UnsupportedInput`；Host 暂将 Touch 作为未处理窗口输入交给应用，不合成鼠标动作。多触点路由与手势、按钮/输入框行为、系统 IME 光标区域、滚动、拖放、无障碍和真实交互验证仍在完整目标范围内。

<a id="animation--按需动画与光标闪烁"></a>

## 按需动画与光标闪烁

已提供与系统时钟无关的控件动画契约，并接通桌面调度与单行输入光标。动画只在需要时请求未来期限，不默认启动持续帧循环。


<a id="animation--分层与时间语义"></a>

### 分层与时间语义

`Widget::animate(elapsed)` 接收应用传入的单调经过时间，返回 `AnimationUpdate { invalidation, next_frame }`。next_frame 是同一时间轴上的绝对期限，必须严格晚于 elapsed；None 撤销本控件的请求。控件负责计算状态和失效范围，不创建线程、计时器或调用系统时钟，也不在此回调发起业务 I/O。

`Tree::advance_animations` 遍历当前节点并合并失效与最早期限。移除节点后不再访问其动画状态；非未来期限返回 InvalidAnimationDeadline，避免立即唤醒形成忙循环。此操作不要求已提交布局，但动画回调不应读取未提供的几何。布局失效仍须在绘制前重新准备。回调发生错误时不承诺所有控件状态回滚，调用方不得继续把失败帧当成成功结果呈现。

初期每次推进扫描当前节点，复杂度为 O(节点数)，不包含独立的活跃动画索引。上层使用单调时间；同一时刻重复调用应保持状态一致。错过多个期限时直接计算当前状态，不循环补绘所有遗漏帧。

WidgetHost 在事件处理和绘制阶段推进状态，通过 Application::animation_deadline 发布期限。Driver 分别保存应用定时器、动画期限与 GPU 重试期限，只向平台提交最早项。动画到期调用 Application::animate，不向应用模型发送业务 Wake；同一时刻多个来源到期，各自处理，不吞掉后续期限。动画的取消和延期不影响其他来源。

隐藏窗口不推进动画，驱动撤销其动画期限；恢复后按当前时间计算。平台底层采用合并期限的既有语义，取消或延期后可能收到一次旧的唤醒，驱动检查各来源的当前期限并忽略它，不触发业务事件或重绘循环。断开连接清除 Host 和驱动的动画调度状态。


<a id="animation--输入光标"></a>

### 输入光标

TextInputView 的 caret_blink_interval 默认 500 ms，表示亮/暗各阶段的长度，完整周期为 1 秒；None 表示常亮，零时长是非法样式。当前不读取操作系统光标闪烁偏好，调用方可显式配置常亮。

聚焦、可编辑且只有插入点时请求闪烁；选区、只读、禁用、失焦和非空预编辑期间不请求闪烁。预编辑光标的显示继续遵守 IME cursor 规则。有效按键、选择变化和组合输入变化会立即恢复光标可见，并从下一次时间推进重新计时。

光标隐藏只影响绘制，不改变排版、选择、横向滚动、IME 候选位置或会话代次。相位计算使用整数时间，延迟帧直接跳到当前相位；时间到达 Duration 表示上限时停止请求无法表示的未来期限。

独立 Tree 使用者需调用 advance_animations 并安排返回的期限；不推进时间时光标保持可见，方便确定性离屏输出。WidgetHost 已完成这一装配。


<a id="animation--验证范围"></a>

### 验证范围

测试覆盖节点期限合并与移除、非法期限、时间跳跃与重置、三种唤醒来源的独立性、隐藏窗口取消，以及真实输入框和 Host 的期限衔接。CPU 像素测试验证亮/暗画面差异、输入后恢复、无重排与候选位置稳定。

当前没有动画曲线、属性插值库、布局过渡编排或大屏特效组件；上述能力可复用此调度契约继续建设。本阶段未进行真实桌面闪烁与系统节能行为验收，也未重跑 GPU 绘制测试。


<a id="animation--定时控件动作补充"></a>

### 定时控件动作补充

菜单等需要在到期后通知应用的控件，可使用 `Widget::animate_with_actions` 与 `Tree::advance_animations_with_actions`。视觉推进接口仍保持原样；窗口宿主通过 `Application::animate_action` 保留定时动作产生的重绘、退出和业务唤醒意图。详见 [菜单悬停容错](advanced-widgets.md#menu-hover)。

<a id="child-viewport--子内容视口与坐标一致性"></a>

## 子内容视口与坐标一致性

`Widget::child_viewport(PaintContext) -> ChildViewport` 是子内容呈现的公共契约，为滚动容器和自定义可平移内容提供基础。核心只读取平移和裁剪值，不感知 ScrollView 或具体控件。布局服务、绘制适配器和平台后端均不需要识别滚动类型。


<a id="child-viewport--契约"></a>

### 契约

`translation` 是相对于容器本地坐标的子内容平移，默认零；向下查看内容通常使用负 y。`clip` 是可选的固定矩形，坐标相对于容器边框盒，在平移子内容之前应用。默认不额外裁剪。两者只作用于后代，不改变容器自身的绘制、命中区域或布局结果。

```rust
fn child_viewport(&self, context: PaintContext) -> ChildViewport {
    ChildViewport {
        translation: Point::new(-self.offset.x, -self.offset.y),
        clip: Some(context.content_bounds),
    }
}
```

上例只是 Widget 方法示意，offset 的范围管理属于控件自身。查询必须是纯函数；状态变化至少请求 Paint 失效，不需要仅为平移重新测量。内容尺寸或视口尺寸变化仍要按正常规则请求 Layout。`Tree::layout_box` 始终返回布局坐标，不返回滚动后的屏幕坐标。

已有 `View::clipped(true)` 仍裁剪节点自身与全部后代，子视口裁剪则仅裁剪后代。两种裁剪可以叠加。子视口不会改变焦点所有权、指针捕获或 Tab 顺序；被裁掉的已捕获控件仍接收按正确局部坐标转换的事件。


<a id="child-viewport--一次操作使用一致的坐标"></a>

### 一次操作使用一致的坐标

核心在构建场景、命中查询和输入分发前建立呈现坐标快照，验证平移、矩形及祖先累加后的坐标。非法值返回 `InvalidChildViewport`，不会发布半个场景或继续分发该次输入。

- 绘制：先画容器自身，再在固定裁剪范围内平移并画后代。
- 命中：反向遍历绘制顺序，使用相同祖先平移与裁剪。
- 输入：从同一次快照计算捕获、目标和冒泡接收者的局部坐标；回调中改变平移在下一次操作生效。
- IME：候选框从焦点控件局部空间转换到窗口空间，并与祖先边框裁剪和子视口裁剪相交；完全不可见或零面积裁剪返回 None。

节点自己的子视口不能裁剪它自己的 IME 区域。嵌套视口逐级累加平移，裁剪留在各自容器坐标中，不跟随内容平移。

快照首次建立仍遍历全部节点并保存 BTreeMap，时间开销为 O(N log N)，额外空间为 O(N)。core 内部通过 Rc 共享不可变快照；没有变化的命中、输入、IME 和绘制查询复用同一份数据。节点变更、布局提交、显式失效及控件返回的 Paint/Layout 失效会清除快照，包含仅平移内容的滚动。一次事件仍持有自己的旧快照，回调产生的变化在下一次操作生效。非法快照不进入缓存。

控件的 `child_viewport` 必须是当前已声明状态的稳定查询；改变平移/裁剪必须报告至少 Paint 失效，不能依赖未声明的内部可变状态刷新坐标。缓存属于 core，不暴露给 app、layout 或 renderer。


<a id="child-viewport--验证与后续"></a>

### 验证与后续

核心测试覆盖嵌套平移、静止裁剪、命中、捕获坐标、IME 裁剪、零面积视口、非法输入恢复和布局不变。顶层渲染测试用仅依赖公共契约的自定义视口，逐像素检查 CPU/GPU 在三种偏移及 1×/2× 缩放下的绘制与命中一致性。

该契约是通用基础。纵向内容测量、范围管理、滚轮/键盘和边界冒泡已由 [ScrollView](layout.md#scroll) 接入；覆盖式滚动条已通过通用前景接口接入；焦点切换后的区域滚入已接入；横向/双向已接入；触摸惯性和虚拟化仍需后续实现。内容高度由实际布局计算。


前景能力通过 Widget::paint_foreground 与 hit_test_foreground 表达，顺序是自身绘制、后代、前景；命中反向执行。前景与自身绘制使用相同本地坐标，不跟随子内容平移，也不受自身 child_viewport.clip 限制，但仍遵守节点和祖先裁剪。默认前景不绘制、不命中，既有控件行为保持不变。核心专项测试验证该顺序及裁剪边界。

<a id="reveal--焦点与区域自动滚入"></a>

## 焦点与区域自动滚入

核心在焦点切换后请求祖先显示目标控件的边框盒。ScrollView 通过公共 `Widget::reveal_child` 契约调整自身偏移，核心不导入滚动控件，也不解释其状态。


<a id="reveal--使用行为"></a>

### 使用行为

- Tab、Shift+Tab、控件请求焦点或 Tree::request_focus 时，焦点节点改变才触发一次自动滚入。
- 若焦点通知同时使布局失效，请求保留到下一次成功发布布局后执行，不使用旧几何。
- 普通重建和尺寸变化不会重复滚入同一个焦点，也不会覆盖用户有意进行的滚轮滚动。需要再次显示该目标时，可显式调用区域请求。
- 目标能放进视口时，仅滚动超出边界所需的距离；已完整可见时保持不动。
- 目标比视口大时采用最近边界，若已经覆盖视口则不动，避免反复调用时来回跳动。
- 当前为立即滚入，不使用动画；禁用的 ScrollView 不响应自动滚入。

应用装配层可在已有 NodeId 时调用：

```rust
tree.reveal_rect(target_id, zui_types::Rect::new(x, y, width, height))?;
```

矩形使用目标节点的本地边框盒坐标。此调用不改变焦点，返回值仅表示是否改变了呈现，不能据此认定目标完全可见。静态祖先裁剪、禁用容器、范围限制或未实现该契约的容器，都可能使目标仍不可见。布局失效时返回 LayoutRequired；非有限、负尺寸或坐标溢出的区域返回明确错误。


<a id="reveal--模块职责与嵌套处理"></a>

### 模块职责与嵌套处理

`Widget::reveal_child(context, area) -> bool` 的接收者只获得本地矩形和自身几何，可修改滚动偏移等呈现状态，并返回是否需要重绘；不得在该回调修改布局或拓扑。默认实现不做任何操作。应用业务状态与具体控件类型不进入核心。

请求从目标向外逐层处理。每次先将目标区域转换到父节点当前呈现坐标，再调用父节点契约；父节点调整子内容平移后，核心将变化应用到区域，并与该层的裁剪相交，再传给外层。因此嵌套滚动先处理内层，外层只处理内层实际能显示的部分。原有绘制、命中与 IME 继续使用统一呈现坐标，无需维护第二套滚动坐标。

核心在回调前验证已有呈现，在完成后验证累加坐标。非法自定义实现造成的状态变更不提供回滚保证；错误会阻止继续按该结果正常处理。回调应保持有限几何且只修改自身呈现。

自动滚入和显式请求不发送 ScrollChanged 用户交互动作，只产生 Paint 失效。滚动范围仍由最近一次布局提供，不能以此接口替代内容测量。


<a id="reveal--验证与后续范围"></a>

### 验证与后续范围

测试覆盖 Tab/反向 Tab、最近边界、手动滚动后重建、尺寸变化、嵌套由内到外处理、重复请求稳定性、超大目标、请求不转移焦点、延迟到有效布局以及非法区域不调用控件。

当前自动目标是整个焦点控件的边框盒；尚未接入输入光标或选区变化时的细粒度区域请求、动画和无障碍请求桥接。横向/双向滚动已按相同契约接入。VirtualList 已支持索引定位和按视口生成行；装配层可先定位并完成布局，再对生成的可聚焦节点调用 request_focus。索引定位本身不转移焦点，跨未生成行的自动焦点导航仍待实现。


<a id="reveal--程序化焦点与验证"></a>

### 程序化焦点与验证

`tree.request_focus(Some(target_id))?` 同时请求焦点和自动滚入，None 清除焦点。目标必须已存在且 enabled、focusable；验证失败保留原焦点。布局未完成时延迟滚入，重复请求不覆盖已成功滚入后的手动滚动，也不改变指针捕获。返回值表示焦点所有者是否改变，不保证目标可见。焦点通知完成后的滚入错误不回滚焦点；尚未完成的滚入可重试。

专项测试覆盖布局前延迟滚入、已布局目标立即滚入、重复请求保留手动滚动位置、清除焦点不改变偏移。虚拟列表测试验证远索引生成后转移焦点，并拒绝已回收的旧 NodeId。


## 局部 View 更新

`ViewApplication::view()` 仍负责首次完整建树；后续 `ViewAction::rebuild()` 合并到准备边界后调用 `view_update(&Tree)`。默认返回 `ViewUpdate::Root(self.view())`，原有应用无需修改。

知道变更范围的应用可返回 `ViewUpdate::Subtree { root, view }`，只构造目标子树。应用根据当前只读树解析节点 ID；多个状态变化应选择共同祖先，无法确定范围时返回 Root。不要复用已卸载节点的 ID，也不要遗漏同批事件改变的其他分支。

```rust,ignore
fn view_update(&self, tree: &Tree) -> ViewUpdate {
    match self.find_counter_node(tree) {
        Some(root) => ViewUpdate::Subtree { root, view: self.counter_view() },
        None => ViewUpdate::Root(self.view()),
    }
}
```

Host 只把更新交给 `Tree::reconcile_subtree`；core 不识别业务消息或具体控件。核心在回调前验证兄弟 key 冲突、绝对深度和整树预算，沿用 key/type 匹配、状态保留、卸载及焦点清理规则。无关分支不执行 View 更新回调；改变目标 key/type 会替换该子树。节点不存在时返回错误，不静默丢弃更新。局部更新并不覆盖后续完整更新或 widget-owned children 的权威描述。

`refresh-bench` 与 `gpu-refresh-bench` 增加 `local_text_scoped`：与 `local_text` 使用相同内容和变化序列，仅缩小描述构造/协调范围。比较性能时同时核对 CPU checksum；离屏结果不代表窗口 FPS。
