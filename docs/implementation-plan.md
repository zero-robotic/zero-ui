实现原则：先建立可运行的纵向功能，再扩展能力；每个 crate 有实际职责，不通过空实现或模拟后端宣称完成。第三方类型留在适配层。每阶段记录真实命令和结果，未验证的平台或功能明确标记。

各阶段共同验收门槛：遵守 [模块分层与依赖约束](module-boundaries.md)，上层通过公开接口使用下层，下层不感知上层；具体服务由装配层注入。新增模块必须明确职责与数据所有权，更新依赖白名单，并完成依赖检查及接口边界审查，保证高内聚、低耦合。

## 阶段 1：双后端绘制基础

已实现：

- `zui-types`：no_std 几何、颜色、逻辑/物理尺寸和仿射变换。
- `zui-paint`：no_std + alloc 路径、填充、描边、嵌套裁剪、作用域变换、离屏契约、预乘 RGBA8 输出与输入预算校验。
- `zui-vello`：仅供适配层使用的公共转换，两个后端不会互相依赖。
- `zui-render-cpu`：Vello CPU 真实绘制、调用方缓冲复用、跨帧重置和尺寸变化。
- `zui-render-gpu`：Vello GPU 真实绘制、离屏回读及适配层直接 TextureView 绘制入口；窗口呈现尚未接入。
- `tools/render-check`：图元预览、CPU/GPU 特性隔离、实际像素回归。
- `tools/check-dependencies.py` 与 CI 定义：内部依赖白名单和单后端传递依赖检查。

锁定 `vello_cpu = 0.3.0`、`vello_gpu = 0.3.0`、`vello_common = 0.3.0` 和 `wgpu = 30.0.1`。依赖要求最低 Rust 1.89；本机实际验证版本为 1.98.1，未宣称已在最低版本测试。

## 阶段 2：桌面窗口与呈现

已接入：

- `zui-platform` 定义窗口、输入、显示指标、像素提交及事件接收契约，不引用应用、winit 或具体渲染器。
- `zui-backend-winit` 实现桌面窗口与输入转换，合并重绘请求，无工作时等待；零尺寸及遮挡窗口保留失效状态。软件表面通过可选 `softbuffer` 提交像素。
- `zui-render-gpu::GpuSurface` 接收原生窗口句柄，选择兼容适配器并直接提交表面，处理尺寸变化和可重试的表面获取状态；不依赖 winit。
- `zui-app` 负责平台与渲染器装配，CPU 复用输出缓冲，GPU 复用深度附件；应用定时任务与 GPU 重试分别保存截止时间，避免互相消耗。
- `tools/window-check` 提供 CPU/GPU 图元窗口、指针与键盘交互及自动退出检查。当前 Application 是场景级入口，尚未包含控件运行时。
- 依赖检查覆盖离屏与窗口两个验证工程的单后端传递依赖；CI 增加 CPU-only、GPU-only 窗口工程严格 Clippy 检查。

本机验证：

- `cargo test --workspace --all-features --offline`：14 项通过，2 项真实 GPU 测试默认忽略。
- 显式运行 GPU 测试：Apple M2 Pro 上 2 项通过，包括裁剪、缩放、透明混合、尺寸变化及双后端图元误差。
- 工作区严格 Clippy、CPU-only/GPU-only 窗口构建检查及依赖检查通过。
- CPU/GPU 窗口各运行 1500 毫秒并正常退出，报告逻辑尺寸 800×480、物理尺寸 1600×960、缩放 2；各完成 2 次重绘。该结果验证实际创建及呈现路径，不代表已完成全部交互或性能验收。

未完成验证：桌面自动化原生连接启动失败，本轮未取得窗口截图，也未执行真实点击、拖动缩放、跨显示器 DPI 切换、最小化恢复或中文输入法交互；输入转换与调度行为目前有单元测试覆盖。Windows/Linux 桌面、GPU 丢失恢复和无 GPU 嵌入式硬件仍待实机验证。布局、文字、控件及后续阶段继续按完整计划推进。

### 后续进展：持久节点与自定义控件

已实现 `zui-core::Tree`，拥有控件实例、节点身份、父子关系、布局结果与失效状态；公共 `Widget` 契约位于 `zui-api::widget`。核心使用注入的 `LayoutEngine`，不引用 Taffy、标准控件或具体后端。

- 节点支持插入、重排、子树迁移及删除；树内 ID 单调分配且不复用。挂载/卸载通过契约通知，删除按子节点先于父节点执行。
- 控件状态随实例保留，重排和迁移不重新挂载。调用方通过泛型 `update_widget` 访问自己提供的控件类型；核心只做通用类型匹配，不包含具体控件的识别分支。
- 区分布局失效和绘制失效；纯绘制修改不重新布局，结构/尺寸修改需重新布局后才能绘制或命中。外部资源变化或替换布局服务时调用方必须显式失效。
- 布局写回在核心中暂存，确保完整且合法后提交；失败不允许发布混合新旧几何的场景。
- 绘制按子节点顺序、命中按逆序；二者共用父级平移和矩形裁剪。尚未接入完整事件传播、焦点、捕获或滚动变换。
- `examples/custom-widget` 是独立编译的 Meter 示例，仅依赖公共 API、paint 和 types。顶层验证工程将其与核心、Taffy 和 CPU/GPU 渲染器装配，证明扩展不需要核心特殊注册。

新增 6 项核心测试及 1 项默认 CPU 集成测试；当前工作区 29 项常规测试通过，另有 4 项真实 GPU 测试在 Apple M2 Pro 上显式通过。自定义 Meter 从 25% 更新到 75% 的全部输出像素经过两种后端检查，且确认未重新布局。依赖门禁覆盖 14 个包，格式和严格 Clippy 检查通过。

当前提供的是命令式持久树基础，不是最终声明式 View API。后续继续实现稳定 Key 协调、消息与事件、文字服务/排版/绘制和主题，并接入窗口。跨帧布局采用粗粒度失效，仍未实现局部布局、绘制缓存或 MCU 实机适配；完整阶段 3 保持进行中。

### 后续进展：声明式 View 与稳定 Key

语义、边界和使用规则见 [View 协调说明](view-reconciliation.md)。下一步继续文字服务与排版/绘制、主题和事件/消息路径；标准容器构造、完整声明式应用装配及后续各阶段仍未完成。

### 后续进展：文字服务与 CPU/GPU 字形绘制

已实现公共 `TextService` 契约和 `zui-text::ParleyText`，锁定 Parley 0.12.0 并开启复杂文字分段数据。显式注册字体后，可执行中文/拉丁文排版、指定宽度换行、最小内容宽度计算、对齐和基线提取。结果持有公共字形序列，绘制不再进行第二次排版。

`zui-paint` 新增字体资源和字形命令，两个 Vello 后端通过内部适配层绘制；文字服务不依赖渲染器，渲染器不依赖文字服务。字体共享所有权保证服务销毁后 Scene 仍有效。进入底层字形库前校验字体格式与集合索引，非法字体返回框架错误；CPU 错误路径验证调用方像素缓冲保持不变。

本机验证：

- 工作区 46 项常规测试通过，其中新增 6 项排版测试和 3 项文字渲染/预算/错误测试。
- Apple M2 Pro 上显式执行 6 项 GPU 回归全部通过，其中新增文字绘制和 CPU/GPU 字形输出对比。文字在 1×、2× 缩放下均验证裁剪内有实际像素、裁剪外无字形泄漏，以及空场景清理。
- 格式、工作区严格 Clippy 与 15 个包的依赖门禁通过，单后端传递依赖保持隔离。
- 已生成并目视检查 `artifacts/text-cpu.png` 与 `artifacts/text-gpu.png`：中文标题、混排段落、组合音标和居中文字正常显示；本次运行无缺少中文分段模型的提示。

范围及资源限制见 [文字服务与字形绘制](text-design.md)，字体来源与许可证见 [字体说明](../assets/fonts/README.md)。尚未完成文本控件、文字测量与控件树的服务注入、编辑/输入法交互、完整字体回退验证、主题和窗口运行时装配。字体预算不是完整进程内存预算，MCU 与无 GPU 嵌入式设备仍需专门适配和实机验证；阶段 3 保持进行中。

### 后续进展：只读文本控件与文字服务注入

新增 `zui-widgets::Text`/`TextView`，仅依赖公共契约，不引用核心、Parley、Taffy 或 Vello。核心通过 `Tree::layout_with_text` 借用文字服务，在测量上下文中传入；字体 epoch 变化触发布局失效。

新增通用 `Widget::prepare` 步骤：完整几何验证后、发布前，向所有控件传入最终内容尺寸。文本控件按最终宽度保存绘制结果，解决多次试测结果不确定及固定宽高跳过测量的问题。准备失败时保留布局失效状态，禁止场景发布和命中，成功重试后恢复；不承诺控件私有缓存回滚。

新增 3 项常规集成测试、1 项 GPU 集成测试，验证自动高度、变窄重排、固定尺寸、内边距、1×/2× 像素结果、颜色更新跳过排版、字体 epoch、错误与恢复。当前工作区 49 项常规测试通过，Apple M2 Pro 上 7 项真实 GPU 测试通过；严格 Clippy 和 16 个包的依赖检查通过。已生成并目视检查 `artifacts/text-widget-cpu.png`，预览通过真实 TextView、Tree 和 Taffy 生成。

目前只读文字不支持选择、编辑或富文本。完整主题、标准容器、事件/消息路径和控件窗口装配仍待实现；阶段 3 继续进行。

### 后续进展：标准布局容器

`zui-widgets` 新增 `Container`、`row`、`column` 和 `grid` 声明式入口，构造普通 View，复用现有布局、协调与裁剪契约。构造器支持样式配置、背景、Key 和裁剪，单子节点 Container 可配置水平/垂直对齐；容器表面不参与命中，后代仍正常命中。仅背景变化产生 Paint 失效；方向、尺寸与子节点顺序变化产生 Layout 失效。

原嵌套 Flex/Grid 预览已迁移到公开容器，删除验证工程的私有 Panel 实现。新增 2 项常规测试和 1 项 GPU 测试，验证内容对齐、背景、裁剪与命中、1×/2× 像素，以及方向切换和 Key 重排保持身份。工作区 51 项常规测试通过，Apple M2 Pro 上 8 项真实 GPU 回归通过；严格 Clippy、格式及 16 个包的依赖检查通过。

用法与边界见 [标准布局容器](containers.md)。尚未提供滚动容器、Stack、Grid 跨轨道放置、主题或容器交互语义。接下来继续主题和应用装配，以及后续事件/消息与交互控件；阶段 3 保持进行中。

### 后续进展：语义主题基础

新增 `zui-theme`，仅依赖基础值类型，采用 `no_std` 且不分配堆内存。提供颜色、字号/相对行高、逻辑间距变量，以及深色、浅色和大屏配色；支持显式局部覆盖和非法数值校验。主题不认识具体控件，不扫描字体，也不引入全局状态。

`TextView::themed` 在构建描述时解析主题值，容器直接使用主题背景与间距。主题切换通过正常属性协调处理：配色变化仅绘制失效，字号/行高与布局间距变化触发重排，无需在核心或渲染器加入主题分支。

新增 2 项常规测试和 1 项 GPU 测试，覆盖非法变量、局部副本隔离、配色切换保留节点/字形并跳过排版、字号/间距变化重排，以及真实像素变化。当前工作区 53 项常规测试通过，Apple M2 Pro 上 9 项 GPU 回归通过；严格 Clippy、格式和 17 个包的依赖检查通过。已生成并目视检查 `artifacts/theme-light.png` 和 `artifacts/theme-dashboard.png`。

使用方式与边界见 [主题变量与更新](theme.md)。圆角、边框宽度、动效变量、交互状态映射和系统主题跟随尚未实现。下一步将持久树、布局、文字和主题装配到窗口应用，再继续事件/消息、交互控件及后续阶段；不将本轮主题基础视为完整主题系统已交付。

### 后续进展：文字服务缺字容错

ParleyText 默认采用 FontPlaceholder 策略，保留整形结果的字形 0 与原始文本几何，避免用户输入未覆盖字符时整个窗口排版失败。严格覆盖检查可在构造服务时指定 Reject；策略在服务生命周期内固定，不引入缓存失效歧义。公共 TextLayout 提供 missing_glyph_count 诊断，表示缺字字形数而非字符数。控件和渲染器无需识别缺字业务状态，预算和其他错误检查保持有效。

新增三项常规测试与一项真实 GPU 测试，并扩展严格模式的交互排版错误检查。验证原始字节范围、视觉移动和选择几何，以及键盘输入、预编辑、提交、删除和撤销。CPU 与真实 GPU 均验证固定 Noto Sans SC 缺字字形在 1×/2× 下产生可见像素。字体自身的字形 0 可能为空，因此不承诺任意字体都显示方框，也不等同于多字体回退和彩色 Emoji 已验收。

完整工作区常规测试、严格 Clippy、格式和 19 包依赖检查通过。真实 GPU 仅运行新增缺字绘制用例，未重跑既有 GPU 用例或原生窗口输入验证。字体策略说明同步到 [文字服务](text-design.md)、[单行输入框](text-input.md) 和 [IME](ime.md)。后续继续完善平台输入验收、剪贴板、导航与其他控件，完整目标保持进行中。

### 后续进展：按需动画与输入光标
