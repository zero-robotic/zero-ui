# 未完成事项与实施约束

本文仅维护尚未完成的能力、待验收范围及持续有效的工程约束，不再保存已完成阶段、历史测试数量、机器环境或冒烟日志。设计目标不等于已交付能力；请求接口、演示数据和可选扩展点不等于完整功能。

## 1. 维护规则

- 完成实现并补齐相应回归后，从待实现清单移除；尚缺真实设备验证的项目转入待验收清单。
- 判断状态时以当前代码及测试为准，不能直接沿用早期文档中的“尚未实现”描述。
- 不把局部完成标为整个框架或整个控件类别完成；每项明确功能边界和验证范围。
- 新增任务前明确所属模块、状态所有者、资源预算与验收条件；不为规划功能建立空 crate。
- 依赖版本以 Cargo 配置和锁文件为准，避免在计划中重复维护版本快照。

## 2. 持续有效的架构约束

### 分层与装配

- 遵守 [模块分层与依赖约束](module-boundaries.md)：上层调用下层公开契约，下层不得识别上层应用、控件或具体类型，不通过全局注册表、类型标签或 feature 绕过依赖方向。
- 公共 API 使用框架自有类型；Taffy、Parley、Vello、winit 等第三方实现类型留在对应适配层。
- 布局、文字、剪贴板、平台与渲染服务由装配层显式注入，不引入隐式全局服务。
- CPU-only 与 GPU-only 保持生产依赖隔离；可移植模块不因新增控件而引入桌面、线程或具体渲染依赖。
- 图表及后续大屏能力放在 `zui-extras` 的可选功能中，不重新拆出无独立边界的组件 crate。

### 状态与交互

- 业务值、选择、展开状态及最终提交由应用持有；控件只发操作意图，不能直接修改其他控件或绕过应用确认。
- 悬停、按压、编辑草稿等局部状态属于控件；焦点、捕获和节点生命周期由核心统一管理。
- 稳定 Key 表达业务身份，不用重排后的索引代替。删除、禁用、绑定变化及失焦应取消不再有效的交互和延迟请求。
- 绘制、命中、事件、焦点显露与 IME 候选区域使用一致的坐标与裁剪契约。
- 虚拟化回收节点不等于保存编辑会话；草稿恢复不等于焦点、捕获或 IME 预编辑保活。
- 时间由上层传入；无工作时等待，不引入默认持续帧循环。业务定时、控件期限和呈现重试不得相互消耗，错过期限不能无界补帧。

### 布局、绘制与错误处理

- 测量和托管子项描述查询必须可重复执行，不产生业务副作用；布局期间不能修改拓扑。
- 校验完整布局后再发布几何；准备或绘制失败不得呈现部分成功帧。不得承诺未实现的全树或控件私有缓存事务回滚。
- 绘制仅生成通用描述，渲染器不读取控件树、不识别控件类型；GPU 回读用于测试、截图或必要适配，不作为原生呈现默认路径。
- 缓存必须覆盖内容、布局、字体和资源变化等失效条件；旧 Scene 与资源快照保持有效，不以哈希相等替代正确性。
- 损伤更新需恢复旧区域，并处理裁剪、透明叠加、缩放与缓存预算；超限回退完整绘制，不能静默漏画。
- 统一控件外观优先复用公共绘制层；专用图元或 shader 需先有测量依据，不能将 CPU 提交变快解释为 GPU 执行变快。

### 资源与可移植性

- 输入、节点、文本、图片、历史、虚拟索引与缓存均需明确预算和超限行为，非法或非有限值不能静默吞掉。
- 单资源限制、缓存统计和空闲草稿预算不等于进程峰值内存或活动编辑总预算；共享快照、临时分配、驱动及第三方缓存另行计入。
- 后台任务使用有界队列与明确取消/过期结果策略，不直接访问 UI 状态；文件、网络与业务采样不进入解码、绘制或索引算法层。
- `no_std + alloc` 和裸机库编译成功不等于 MCU 可运行；仍需分配器、原子能力、字体、显示驱动及真实内存预算验证。

## 4. 待验收范围

以下事项应与“未实现”区分：已有代码、单元测试或离屏回归，不代表已完成目标环境验收。

- [ ] 原生窗口逐项鼠标/键盘交互、拖动缩放、最小化恢复、跨屏 DPI、焦点与弹层切换。
- [ ] 中文 IME 组合/取消/提交、候选窗口定位，以及跨应用剪贴板互操作。
- [ ] Windows/Linux 桌面、Wayland 合成器差异及 GPU 丢失/恢复路径。
- [ ] 多字体回退、复杂双向文本、彩色 Emoji 与字体热替换的能力和表现。
- [ ] 真实文件/网络图片加载、长时显存及内存稳定性。
- [ ] 大规模布局、编辑、虚拟列表和实时大屏的 CPU/GPU 耗时、端到端帧时间、峰值资源及空闲能耗。
- [ ] 无 GPU 嵌入式 Linux 实机的显示、输入、布局与渲染性能。
- [ ] MCU 固件链接、分配器、显示设备、受限布局/文字/渲染适配及其他目标架构。
- [ ] 最低 Rust 版本与目标平台 CI 矩阵的实际运行验证。

## 5. 验收门槛

- 按改动范围运行专项回归，再扩展到工作区检查；持续检查格式、Clippy、依赖方向与 CPU/GPU 特性隔离。
- 可移植模块改动需运行 MCU 边界检查；编译结果不能替代设备验证。
- 绘制改动需验证实际像素、缩放、裁剪、透明叠加、资源替换与错误恢复；需要真实 GPU 的用例必须单独说明是否执行。
- 交互改动覆盖受控值确认/拒绝、稳定身份、键盘、禁用、捕获/焦点丢失、迟到事件及布局变化。
- 性能结论必须说明工作量、设备、计时边界和正确性校验；分别记录 CPU 准备、GPU 完成与显示链路，不从离屏耗时推断真实窗口 FPS。
- 记录实际执行与未验证范围，不以模拟数据、限时退出、编译通过或请求接口代替完整交付。
